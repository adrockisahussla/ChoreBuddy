## What the product is

**ChoreBuddy** = a family system with three faces:

1. **Mobile app** (Android, sideloaded via GitHub releases) — chores, rewards, reminders, invites, GameWall (screen-time + remote PC firewall).
2. **Windows agent** (sideloaded via GitHub releases) — runs as a service on a kid's PC, takes commands from the mobile app to block/allow games + browsers.
3. **Firebase backend** — Firestore (data + rules), Realtime Database (RTDB, command channel to the agent), Firebase Auth (Google sign-in), Hosting (invite landing page).

### Command channel (RTDB → agent)

Mobile writes `firewallControl/{machineId}/control = { command, timestamp }` to RTDB. Agent's SSE stream fires `OnControlEvent` → `ApplyCommand`. Commands:

- `shutoff` — block configured apps + games. Pauses ScheduleEnforcer.
- `allow` — unblock everything. Pauses ScheduleEnforcer.
- `update` — agent self-updates from GitHub releases immediately.
- `reload-schedule` — agent refetches `gameSchedules/{kidId}` from Firestore (one read).
- `resume-schedule` — clears the paused flag + re-evaluates.

## What's been built (high-level)

This session and the preceding one. Read `CHANGELOG`-style commit history in both repos for fine detail.

### Chore lifecycle
- Pool templates + per-buddy assignment with `Save & Assign` flow.
- Submit (kid) → notify assigner (toast + Notifee + persistent flag).
- Approve (manager) → kid sees `🎉 APPROVED — GO COLLECT` celebration.
- Collect (kid taps coin) → points actually bank. Wallet animates.
- Reject (manager) → kid gets `useRejectedChoreNotifier` toast.
- All toasts queue via `src/utils/toastQueue.ts` (paces ToastAndroid 2.5s apart).

### Rewards
- Per-kid `rewardPool` catalog of "X minutes screen time for Y points".
- Kid redeems → `rewardClaim` pending → manager fulfills → `users/{kid}.minutesRemaining` increments atomically (`FieldValue.increment`).
- Manager-side delete on past claims only for `denied` (preserves the spent math on `approved`).
- Family-wide pool entries (kidId='') visible to every kid.

### GameWall (screen-time firewall)
- Manager Drawer → GameWall → buddy list → tap a buddy → BuddyScheduleScreen.
- Per-day mode toggle (v1.39): **Time window** OR **Daily cap**. Mutually exclusive.
- Save → `gameScheduleService.save` writes to Firestore + pushes `reload-schedule` RTDB command to every PC paired with that kid. Agents on v1.0.2+ refetch once.
- Manual override buttons (Block now / Allow now) pause the agent's enforcer. **▶ Resume schedule** button on the per-buddy page unpauses.
- "🚀 Update all PCs (N)" button at top of GameWall (instant agent self-update).

### Windows agent (high-level)
- Setup wizard with Google sign-in + buddy picker.
- Per-PC: `firewallControl/{machineId}` Firestore doc + RTDB control node.
- `FirewallManager` blocks via three mechanisms simultaneously: process tree kill, IFEO Debugger registry shim, netsh outbound rule.
- `BannedPopupForm` (full-screen 🚫 takeover) fires when a kid double-clicks any blocked .exe.
- `SteamRestarter.CleanRestart` runs on ALLOW so Steam comes back online instead of stuck offline.
- `ScheduleEnforcer` enforces the GameWall schedule locally (60s tick, no polling).
- `AgentUpdater` self-installs new releases hourly.

### Settings / safety
- Mobile Settings → Reminder permissions card with three deep links + "Send test reminder" diagnostic.
- Mobile Settings → "Cancel alarms on sign-out" toggle (per-account flag in `users/{uid}.cancelAlarmsOnSignOut`) — for shared phones.
- Push notifications for chore submit / approve / reject / claim resolve / new assignment via Notifee.

### Windows agent
**Read this first:** the watchdog scheduled task auto-restarts the service every minute and re-locks the .exe, making `dotnet build` silently fail. Always do this sequence:

```powershell
# 1. Stop the watchdog so it doesn't re-launch the service mid-build
Unregister-ScheduledTask -TaskName ChoreBuddyAgentWatchdog -Confirm:$false

# 2. Stop the service + kill any interactive instance
Stop-Service ChoreBuddyAgent
Stop-Process -Name ChoreBuddy.TestApp -Force -ErrorAction SilentlyContinue

# 3. Rebuild
cd "C:\Users\NWI - E02\Desktop\ChoreBuddy-Agent\src\ChoreBuddy.TestApp"
dotnet build

# 4. Verify
(Get-Item ".\bin\Debug\net8.0-windows\ChoreBuddy.TestApp.exe").LastWriteTime
# Should be within the last minute. If not, you ran the swap wrong.

# 5. Restart
Start-Service ChoreBuddyAgent
```

## Known traps for the next agent

1. **Don't trust git HEAD on the mobile repo.** It chronically lags behind the working tree. Read actual files in `src/` to know current behavior.
2. **Watchdog trap** (see "Build + ship cheatsheets" above). Always unregister before rebuilding.
3. **Steam offline after ALLOW** — addressed via `SteamRestarter.CleanRestart`. If you ever regress this, see `docs/HANDOFF-steam-not-running-after-allow.md`.
4. **IFEO entries** — the `--banned` popup only fires for .exes the agent has IFEO-blocked. Steam library scan only happens during SHUTOFF when `KillRelated=true`. If a game isn't blocked, the kid sees a normal Steam-offline error from the game itself, not our popup. Not a bug.
5. **In-app updater silent failures** — historically buggy on poor cellular. Hardened in v1.17 (5-min timeout, retry, manual redirect). Always-available fallback: open the invite landing page in mobile Chrome.
6. **Agent OAuth secrets** are gitignored (`Secrets.cs`). Don't commit. The example file shows the shape.
7. **App Check** is intentionally disabled. Re-enabling requires Play Integrity API enabled in Cloud Console; otherwise Firestore writes fail with a misleading "caller doesn't have permission" attestation error.
8. **Schedule push doesn't unpause.** Saving a new schedule pushes `reload-schedule` but does NOT clear `SchedulePaused`. The manager has to tap **▶ Resume schedule** explicitly. This is intentional — manual override always wins.
9. **Firestore quota** — agent never polls. Reads are bounded: heartbeat (config + machine info) every 5 minutes per machine, plus 1 schedule fetch per phone-push. Stay push-only on any new agent-side feature.
10. **`firewallControl` is keyed by machineId, not kid uid.** Agents write `kidId` into the doc so mobile can filter. If you ever join across these, query by `where('kidId', '==', ...)`.
